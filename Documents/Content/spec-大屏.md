# spec-大屏

运行形态：Web 页面，HTML + JS + ECharts，深色数据大屏风格。面向对象：运营决策者。大屏不产生业务数据，只汇总呈现；数据全部来自服务端 WebSocket 推送或快照拉取，不直连数据库。消息类型见 `spec-协议.md`。

## 定位与数据链路

数据链路：服务端设备模拟/采集线程写库 → 预处理聚合 → 分析层（含机器学习）产出指标 → ECharts 渲染。核心指标秒级刷新，图表按分钟级窗口滚动。预测结果以虚线/弱化色区分"实际已发生"与"预测未发生"。

## 页面布局（运营驾驶舱）

宽屏栅格，自上而下四排：

| 位置 | 区域 |
| ---- | ---- |
| 第一排 | 四张核心指标卡：今日营收、今日订单、当前充电、在线充电桩 |
| 第二排 | 左：充电站分布地图；右：实时功率负荷曲线 |
| 第三排 | 四块图表：利用率 TOP10、实时告警、用户增长趋势、峰谷电量分析 |
| 底部 | 实时订单/事件滚动流 |

## 模块规格

### 核心指标卡【基础】

- 数据：今日营收（元）、今日订单（笔）、当前充电（台）、在线充电桩（%）。
- 规则：每张卡带数值、单位、环比/趋势标识；与 `spec-管理端` 销售业绩共用口径。秒级刷新，数字滚动动画。
- 消息：`screen.snapshot` 快照 + 增量推送。
- 验收：四卡数值与数据库统计一致，秒级自动更新。

### 充电站分布地图【基础】

- 数据：全部电站经纬度打点，点色按当前负载区分（空闲充足/接近满载/拥堵）。
- 规则：点击站点浮出空闲桩数、当前负载、今日营收摘要。
- 图表：ECharts `scatter` / `map`。
- 验收：点位与 `station` 经纬度一致，hover/点击出现摘要。

### 实时功率负荷曲线【基础】

- 数据：全网或所选站点功率负荷随时间变化（纵轴 kW，横轴时间）。
- 规则：曲线叠加机器学习的分时负荷预测（未来 1/6/24 小时），实线=实际、虚线=预测、阴影=置信区间。
- 消息：`ml.forecast` / `push.forecast`。
- 验收：实际曲线实时滚动，预测曲线按时段叠加且线型可区分。

### 利用率 TOP10【基础】

- 数据：各站利用率降序。
- 图表：横向条形图，降序 + 圆角渐变。
- 验收：与数据库计算口径一致，顺序正确。

### 实时告警【基础】

- 数据：当前设备与站点告警（类型/级别/时间）。
- 规则：与管理端设备告警联动，同一告警在大屏与管理端同时出现。
- 消息：`push.alarm`。
- 验收：模拟故障后告警同时出现在两处。

### 用户增长趋势【基础】

- 数据：新增注册趋势。
- 图表：折线图。
- 验收：与 `user.register_time` 统计一致。

### 峰谷电量分析【基础】

- 数据：电量在谷/平/峰时段分布。
- 图表：堆叠柱状图或饼图，三色呼应电价档位。
- 验收：各时段电量合计等于总充电量。

### 实时事件滚动流【基础】

- 数据：全平台关键事件逐条滚动，带时间戳。示例：

```
16:21:08  用户 138****8241 在 XX 站 A03 开始充电
16:21:10  XX 站 A07 发生通信异常
16:21:15  用户 189****4421 完成充电
16:21:20  XX 站负荷达到 92%
```

- 消息：`push.order_event`、`push.alarm`、`push.charger_status`。
- 验收：事件实时滚播且与数据库记录对应。

### 碳排统计与绿色充电指数【增强】

- 数据：今日充电量、服务车辆、今日减碳（吨）、累计充电量、累计减碳（吨）；绿色指数 0–100 拆解为谷时充电比例、绿电使用比例、峰值负载降低、碳排放减少四项构成。
- 图表：数字卡 + 居中 gauge/环形图。
- 碳排因子 `[待定]`（建议初值 0.7 kg/kWh）。
- 验收：指数为四项构成的加权结果，数值可复算。

### 机器学习联动可视化【增强】

- 数据：负荷预测曲线（叠加实时曲线）；需求预测以"未来时段需求热力"呈现；设备健康度聚合为"设备可用率/健康度分布"图并标识高风险设备。
- 规则：预测一律以虚线/弱化色区分。
- 验收：预测与风险数据来自 `spec-机器学习` 产出，标识清晰。

### 评价与反馈分析【增强】

- 数据：站点/全网评价标签分布与趋势、评分分布（分维度）、用户最常反馈问题 TOP5 占比。
- 规则：标签频次与环比（如"XX 站排队严重标签 30 天增长 42%"）；反馈 TOP5（设备故障/停车问题/等待时间/价格问题/服务问题）占比饼图；评分按充电速度/设备/停车/卫生/服务分维度条形或雷达。形成"用户评论 → 数据分析 → 运营决策"闭环。
- 消息：`screen.snapshot` 扩展 + `push.review`。
- 验收：标签趋势与 `review` 数据一致，可下钻到具体站点。

## 开发与数据接入

- 无真实数据时先用假数据 JSON 独立跑通页面（`file://` 打开），联调阶段再替换为 WebSocket 数据源。
- 数据源：服务端 WebSocket 推 JSON；联调不顺时退化为 `setInterval` 轮询服务端定期写出的 `data.json`。
- 建议直接用深色大屏模板改数据源绑定，优先保证视觉效果。
