# spec-增强功能池

本文件收纳历次讨论（含与 GPT 的脑暴）产出的**方向性扩展想法**，是"功能菜单"而非承诺范围。基线范围以各 `spec-*.md` 为准，`【基础】`必做，`【增强】`为已定稿的可裁剪项；本池中的想法**只有在被"提升"进对应 spec 后才进入实现范围**。

## 使用说明

- **提升**：把一个池内想法写进对应 spec 的 `【增强】`小节（补全触发/规则/输入输出/验收）后，AI 才会按它实现。
- **挑选原则**：优先挑"一个功能服务多个模块"的想法（如评价 → 数据分析 → 告警 → 处理），避免为了加功能而堆页面。
- **分级**：标注「已提升」表示已进入某 spec；「待决策」表示平台级改动需团队拍板；其余为可选项。
- 本池不设完整五要素规格，提升时才补全。

## 二、平台级方向（待决策，改动大）

这些想法会改变数据模型或产品叙事，需要团队拍板后再决定是否提升。

### P1 定位升级：智慧电动交通补能平台

- 想法：把"电动汽车充电站系统"升级为"智慧电动交通补能平台"，覆盖汽车快/慢充、两轮车充电/换电、运营商自营/合作、用户消费与社区、AI 预测/诊断/决策。
- 影响：README 定位、00 架构叙事、子系统划分、数据库模型都要跟着变。
- 现状：基线保留老师要求书的"电动汽车充电桩应用管理平台"定位；本项作为叙事备选。
- 决策点：答辩要讲"多类型补能 + 智能运营"就升级；要稳就保留。

### P2 车辆三维模型（车辆 → 补能方式 → 接口/电池规格）

- 想法：不按"汽车/两轮/三轮"硬分，而是三维度：车辆类型（乘用车/轻商/两轮/三轮）、补能方式（插枪/扫码/换电）、接口/电池规格（国标交/直、其他、XX 电池）。系统只推荐兼容设备；换电场景变为"找换电站"。
- 影响：`user`/`charger`/`station` 模型与推荐引擎改造，需新增换电设备类型。
- 现状：已做最小版"我的车辆"（vehicle 表），完整三维模型与换电属本项范围。

### P3 站点类型（自营/加盟/合作/第三方）

- 想法：平台定位为聚合平台，站点分自营/加盟/合作/第三方；用户看整个生态，后台"我的运营站点"只管理自己的。
- 影响：`station` 增加 `owner_type` 字段与商户关联表。
- 现状：可最小化落地为 `station.owner_type` 一个字段 + 管理端筛选。

### P4 商户/站点合作管理

- 想法：后台商户管理（名称、合作站数、结算金额、订单数、服务评分、合作状态），月度应结算统计。
- 影响：新增 `merchant` 表与结算逻辑，属平台型业务扩展。
- 前置：P3。

### P5 财务中心

- 想法：交易流水、充值记录、订单、退款、优惠抵扣、平台收入、商户结算、今日实收/待结算/已退款。
- 影响：新增流水类表与统计页。
- 前置：无，但工作量大。

### P6 数据分析中心

- 想法：用户/订单/设备/站点/收入/时段/车型/区域/评价/故障十个分析维度，可回答"快充慢充收入占比""哪个站满意度最高""哪个时段故障率最高"。
- 影响：管理端新增分析页，可复用 AI 助手与机器学习产出。
- 前置：部分可先并入 AI 助手问答。

### P7 规则引擎与运营策略实验室

- 想法：运营人员自己配置规则（空闲率<20% 自动推荐他站、健康度<60 自动建工单、排队>5 触发拥堵告警）；策略实验室对"降电价/发券/引导分流/限预约"多方案做 what-if 对比并推荐。
- 影响：管理端新增"规则配置"与"策略模拟"页，本质是 if-else 配置化 + 复用现有 what-if 推演。
- 前置：what-if 已存在（`spec-管理端`），本项在其上做配置化与多方案对比。

## 六、验收口径提醒

从池中提升任何想法时，遵循「一个功能服务多个模块」：评价 → 数据分析 → 告警 → 处理 → 再评价；天气 → 推荐 → 预测 → 告警 → 优惠策略。避免为了加功能而堆页面。
