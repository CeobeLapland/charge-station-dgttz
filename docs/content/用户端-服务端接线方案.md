# 用户端-服务端接线方案

> 目的：明确用户端（user/）接服务端（server/）的范围、方法与缺口，供开工前评审。
> 状态：草案（待评审）
> 依据：`docs/content/spec-协议.md`（消息权威）、`docs/content/spec-用户端.md`（功能权威）、`server/README.md` 与 `server/src/WsServer.cpp`（服务端现状，已逐条核实）。

## 0. 结论速览

- **协议是对齐的**：服务端严格按 `spec-协议.md` 实现信封（`type`/`seq`/`code`/`message`/`payload`）、错误码、响应类型（请求 type + `_resp`，心跳例外回 `system.pong`）。
- **用户端网络层已就绪但闲置**：[UserClient.cpp](file:///home/bit/projects/charge-station-dgttz/user/src/UserClient.cpp) 已实现信封收发与解析，注册为 QML 的 `backend`，但**全仓库 QML 没有一处调用它**。当前 UI 全部跑在本地 mock（`AuthStore` / `ExploreData` / `UserData` / `ChatData` / `ChargingFlow`）。
- **接线方式**：不动 QML 页面绑定，示例数据先不删除，把 C++ 数据源（ExploreData / UserData / ChargingFlow）的内部实现从「本地 mock」换成「WebSocket 请求 + 缓存响应」，QML 绑定基本不变。
- **缺口分三类**：✅ 服务端已实现可直接接；⚠️ 服务端有但参数/字段不全需降级；❌ 协议或服务端没有，保持本地示例。⚠️/❌ 的取舍见第 5 节决策清单。

## 2. 各功能接线明细

### 2.1 连接与登录

- 启动即 `backend.connectServer("ws://127.0.0.1:9000")`；登录页点登录 → `backend.login(phone)`（即 `user.login`）。
- `user.login_resp` 成功返回 `{user, created}`，服务端把身份绑定到这条连接；**后续请求一律不再传 `user_id`**。
- 「自动登录」可保留：本地 QSettings 存手机号，启动后直接发 `user.login`。
- **登录模型差异**：用户端现有「账号+密码注册/登录」是本地假功能，服务端是手机号免密（不存在自动注册）。决策：
  - 登录页改为只输手机号（✅ 有服务端支持）；
  - 注册页 / 找回密码页 / 切换账号里的密码逻辑无服务端消息 → 保持本地示例或隐藏（决策项 D1）。
- 被冻结用户返回 `1003`，未登录访问返回 `1004`，需在登录页/全局做错误提示。

### 2.2 附近电站与电站详情

- `station.nearby {longitude, latitude}` → 按距离排序返回 `stations[]`，替换 `ExploreData.stations()` 的距离排序。
- `station.detail {station_id}` → 返回 `station` + `chargers[]`，替换 `ExploreData.chargersForStation()` 与价格规则。
- **服务端返回字段 vs QML 期望字段差异**（`station.nearby` 只回 11 个字段，QML 卡片用 20+）：

| 服务端已返回 | QML 期望但服务端没有 |
| --- | --- |
| id, name, address, area, longitude, latitude, total_chargers, free_chargers, service_fee, price, distance | rating, rating_count, fast_count/slow_count, fast_idle/slow_idle, online_rate, parking_fee, business_hours, facilities, owner_type/owner_label, merchant_id/merchant_name, has_swap, offline_count, fault_count, charging_count, weather_area, area_province/city/district |

- **处理策略**（决策项 D2）：服务端缺失的展示字段由客户端生成「示例/随机种子」补齐（如按 total_chargers 推算快慢分项、评分给默认值），不阻塞接线；如果希望真数据，需服务端在 `station.nearby`/`station.detail` 补字段。
- 天气 / 省市区 / 商户 / 推荐等无协议来源 → 保持 ExploreData 本地示例。

### 2.3 充电全流程（ChargingFlow 替换核心）

ChargingFlow 设计时已按「mock 方法 ↔ 协议消息」一一对应（见 [ChargingFlow.h](file:///home/bit/projects/charge-station-dgttz/user/src/ChargingFlow.h) 头注释），接线即把 mock* 方法体换成 `backend.send(...)`：

| ChargingFlow mock 方法 | 对应协议消息 | 服务端现状 |
| --- | --- | --- |
| `mockReserve` / `mockTryMatch` / `mockAdvanceQueue` | `reservation.join {station_id}` + `push.reservation_notify` | ✅ 排队可用，返回 `reservation` + `queue{ahead_count, estimate_start_time}` |
| `mockAssignCharger` | （排队匹配后服务端直接分配） | ✅ 服务端匹配空闲桩并回填 charger |
| `mockStartScanDeadline` / `mockScanTick` | `push.order_timeout` / `push.reservation_timeout` | ⚠️ 服务端**未实现**扫码超时/排队超时推送，客户端仍可保留本地倒计时 |
| `confirmScan` | `order.create {charger_id}` → 取 `order.id` → `order.start {order_id, start_soc}` | ✅ 已实现（start 后电桩置 charging 并启动仿真） |
| `mockStartCharging` / `mockProgressTick` | `push.order_progress`（服务端每秒定向推送） | ✅ 替代本地进度定时器，客户端只显示推送值 |
| `mockFinishCharging` | `order.finish {order_id}`（可不传 end_soc，服务端用仿真值） | ✅ 转待结算，电桩回 idle |
| `mockSettle` | `order.settle {order_id, points_used?}` | ✅ 返回 order/points/balance/total_points |
| `cancel` | `reservation.cancel {reservation_id}` / `order.cancel {order_id}` | ✅ |
| `mockApplyPenalty` | 违约扣款 | ⚠️ 服务端未实现违约金/占位费逻辑 |

- **服务端不支持、客户端需降级/删减的参数**（决策项 D3）：
  - **定时预约**：`reservation.join` 服务端只收 `station_id`，`reserve_type`/`expect_time` 不认 → 定时预约先降级为即时排队，或前端只保留"立即充电"。
  - **选车**：`order.create` 不传 `vehicle_id`，服务端自动取用户默认车辆；表单选车可保留但结果按默认车结算。
  - **目标电量**：`order.start` 后服务端固定 `target_soc=100`（充满自动结束）；前端目标电量选择框服务端忽略。
  - **快慢偏好**：服务端排队/下单不区分 fast/slow，仅桩本身类型决定。

## 3. 架构改造点（怎么接）

1. **UserClient 增强**（[UserClient.h](file:///home/bit/projects/charge-station-dgttz/user/src/UserClient.h)）：
   - 请求-响应关联：按 `seq` 匹配回调（现在 QML 只能靠 type 分辨，加一层 `send(type, payload, cb)` 或 QML 端按 type 分发均可）；
   - push 路由：`push.order_progress` / `push.reservation_notify` / `push.charger_status` 等无 seq，单独分发；
   - 心跳：每 15s `system.ping`，收到 `system.pong` 续期；断线重连。
2. **数据桥接层**：现有 QML 数据源是同步 `Q_INVOKABLE`，WebSocket 是异步。建议在 C++ 层建「最近缓存 + changed 信号」：
   - `UserData` / `ExploreData` 保留原同步方法签名（QML 绑定不动），内部改为"从缓存读"；登录/刷新时拉数据写缓存并发 `xxxChanged`。
   - 或新增 `UserApi` 类统一管理，QML 页面改为异步回调（改动较大，不建议先做）。
3. **ChargingFlow 替换**：mock* 方法体改为 `backend.send` + 监听响应与 push；本地进度/占位定时器删除，进度一律用 `push.order_progress`。
4. **错误码处理**：QML 统一处理 `code != 0`，对照 `spec-协议.md` 错误码表提示（1003 冻结、1004 未登录、2002 余额不足、2003 状态不允许、4001 不存在等）。

## 4. 关键约束（来自服务端，写代码时必须遵守）

- **身份一律取自连接**：登录后服务端在会话上绑定 user_id，payload 里的 `user_id` 一概忽略。用户端所有消息不要传 `user_id`。
- **订单归属**：不是自己的订单一律按"不存在"（4001）处理，不区分不存在与不是你的。
- **时间格式**：一律本地时间 `yyyy-MM-dd HH:mm:ss`。
- **`order.finish` 不传 `end_soc`**：服务端用仿真器当前电量结算，客户端不要自己维护 SOC，直接用 `push.order_progress` 的 `soc` 展示。
- **充值门槛**：余额 < 10 元不允许 `order.start`（2002）。
