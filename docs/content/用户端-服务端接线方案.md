# 用户端-服务端接线方案（v2）

> 目的：明确用户端（user/）接服务端（server/）的范围、方法与缺口。
> 状态：v2（2026-09-07，服务端新增个人域接口后复核更新）
> 依据：`docs/content/spec-协议.md`、`docs/content/spec-用户端.md`、`server/README.md`、`server/src/WsServer.cpp`（已逐条核实）。
>
> **原则（定死）**：① 绝对不删任何功能；② 缺数据一律用示例/种子数据补齐展示；③ 服务端能接多少接多少，接不上的保留本地 mock 兜底；④ 老师只看演示视频。

## 0. 结论速览

- **协议对齐**：服务端严格按 `spec-协议.md` 实现信封/错误码/响应命名；用户端 [UserClient.cpp](file:///home/bit/projects/charge-station-dgttz/user/src/UserClient.cpp) 网络层已就绪，但 QML 还没调用，UI 全部跑在本地 mock。
- **服务端现状（新版本）**：除充电核心链路外，已补齐**个人域全部接口**——收藏、消息通知、积分、会员套餐、优惠券、评价、天气、FAQ。用户端 UI 用到的功能几乎全有服务端对应。
- **接线方式不变**：不动 QML 页面绑定，把 C++ 数据源（`ExploreData` / `UserData` / `ChargingFlow`）的内部实现从本地 mock 换成「WebSocket 请求 + 缓存响应」，QML 绑定基本不动。
- **剩余缺口（很小）**：聊天无协议、省市区/商户无消息、`station.nearby` 展示字段不全、充电参数（定时/选车/目标电量/快慢）服务端忽略、扫码超时/占位/违约无推送、充电画像返回空。全部按"示例兜底"处理，不阻塞。

## 2. 各功能接线明细

### 2.1 连接与登录

- 启动即 `backend.connectServer("ws://127.0.0.1:9000")`；登录页点登录 → `backend.login(phone)`（即 `user.login`）。
- `user.login_resp` 成功返回 `{user, created}`，服务端把身份绑定到这条连接；**后续请求一律不再传 `user_id`**。
- 「自动登录」保留：本地 QSettings 存手机号，启动后直接发 `user.login`。
- 登录模型差异：服务端是手机号免密（不存在自动注册）。登录页改为只输手机号；**注册页/找回密码页/切换账号里的密码逻辑保留本地示例（不删）**。
- 被冻结返回 `1003`、未登录访问返回 `1004`，登录页/全局做提示。

### 2.2 附近电站与电站详情

- `station.nearby {longitude, latitude}` → 按距离排序的 `stations[]`，替换 `ExploreData.stations()` 的距离排序。
- `station.detail {station_id}` → `station` + `chargers[]`，替换 `ExploreData.chargersForStation()`。
- **字段差异**：`station.nearby` 只回 11 个字段（id/name/address/area/longitude/latitude/total_chargers/free_chargers/service_fee/price/distance），QML 卡片还用了评分、快慢桩分项、设施、营业时间、停车费、商户、weather_area 等 → **这些缺字段客户端用示例/随机种子补齐**（如按 total_chargers 分快慢、评分给默认值），不阻塞。
- 天气：`weatherForArea(area)` → `weather.get {area}`（免登录，返回 condition/temperature/forecast/update_time）。
- 省市区、商户、推荐：无协议消息 → 保持 ExploreData 本地示例。

### 2.3 充电全流程（ChargingFlow 替换核心）

ChargingFlow 的 mock 方法 ↔ 协议消息已一一对应（见 [ChargingFlow.h](file:///home/bit/projects/charge-station-dgttz/user/src/ChargingFlow.h) 头注释）：

| ChargingFlow mock 方法 | 对应协议消息 | 服务端现状 |
| --- | --- | --- |
| `mockReserve` / `mockTryMatch` / `mockAdvanceQueue` | `reservation.join {station_id}` + `push.reservation_notify` | ✅ 排队可用，返回 `reservation` + `queue{ahead_count, estimate_start_time}` |
| `mockAssignCharger` | 服务端匹配后直接分配 | ✅ |
| `mockStartScanDeadline` / `mockScanTick` | `push.order_timeout` / `push.reservation_timeout` | ⚠️ 服务端未实现超时推送 → **保留本地倒计时示例** |
| `confirmScan` | `order.create {charger_id}` → 取 `order.id` → `order.start {order_id, start_soc}` | ✅（start 后电桩置 charging 并启动仿真） |
| `mockStartCharging` / `mockProgressTick` | `push.order_progress`（每秒定向推送） | ✅ 替代本地进度定时器，客户端只显示推送值 |
| `mockFinishCharging` | `order.finish {order_id}`（可不传 end_soc） | ✅ 转待结算 |
| `mockSettle` | `order.settle {order_id, points_used?}` | ✅ 返回 order/points/balance/total_points |
| `cancel` | `reservation.cancel {reservation_id}` / `order.cancel {order_id}` | ✅ |
| `mockApplyPenalty` | 违约/占位费 | ⚠️ 服务端未实现 → **保留本地示例** |

- **服务端忽略、客户端降级的参数（表单保留，结果按服务端默认）**：
  - 定时预约：`reservation.join` 只收 `station_id`，`reserve_type`/`expect_time` 不认 → 定时入口降级为即时排队。
  - 选车：`order.create` 不传 `vehicle_id`，服务端取用户默认车辆。
  - 目标电量：`order.start` 后服务端固定 `target_soc=100`（充满自动结束）。
  - 快慢偏好：服务端不区分 fast/slow 排队，仅桩类型决定。

## 3. 架构改造点（怎么接）

1. **UserClient 增强**（[UserClient.h](file:///home/bit/projects/charge-station-dgttz/user/src/UserClient.h)）：
   - 按 `seq` 关联请求-响应（或 QML 按 type 分发）；
   - push 路由：`push.order_progress` / `push.reservation_notify` / `push.charger_status` / `push.review` 等无 seq，单独分发；
   - 心跳：每 15s `system.ping`，断线重连。
2. **数据桥接层**：QML 数据源是同步 `Q_INVOKABLE`，WebSocket 是异步 → C++ 层做「最近缓存 + changed 信号」，`UserData`/`ExploreData` 保留原同步方法签名（QML 绑定不动），内部改为从缓存读；登录/刷新时拉数据写缓存并发信号。
3. **ChargingFlow 替换**：mock* 方法体改为 `backend.send` + 监听响应与 push；本地进度定时器删除，进度用 `push.order_progress`。
4. **错误码处理**：QML 统一处理 `code != 0`，按 `spec-协议.md` 错误码表提示（1003 冻结、1004 未登录、2002 余额不足、2003 状态不允许、4001 不存在等）。

## 4. 关键约束（来自服务端，写代码时必须遵守）

- **身份一律取自连接**：登录后服务端在会话上绑定 user_id，payload 里的 `user_id` 一概忽略，用户端所有消息不要传 `user_id`。
- **订单归属**：不是自己的订单一律按"不存在"（4001）处理。
- **时间格式**：一律本地时间 `yyyy-MM-dd HH:mm:ss`。
- **`order.finish` 不传 `end_soc`**：服务端用仿真器当前电量结算；客户端不维护 SOC，直接用 `push.order_progress.soc` 展示。
- **余额 < 10 元不允许 `order.start`**（2002）。
