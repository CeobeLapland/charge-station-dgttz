## 2. 接下来几天的三档目标（按性价比排序）

### 目标 A：让大屏真的查 Hive（高优先，工作量小，演示价值大）
现在 `/hadoop` 页能独立查 Hive，但大屏还喂 mock。把这层打通，大屏指标就来自真实 Hive 聚合 → 面子上最满足"大数据平台"。

**做法（我们来改）：** 在 Python 网关 `app.py` 里加一个 `/api/snapshot` 接口，它内部拼几条 Hive 聚合 SQL：
- 六项核心指标：`select count(*) 站点, sum(total_chargers) 桩 from station`、`select count(*) 今日订单 from charging_order where create_time ~ 今天`、`sum(pay_amount) 今日收入` …
- 状态分布：`select status,count(*) from charger group by status`
- 近7天趋势：`select date(create_time),sum(energy_kwh),sum(pay_amount) from charging_order group by 日期`
- 站点排行：订单 join 站点 group by 站点
- 站点地图：`select id,name,area,longitude,latitude from station`
前端 `store.js`/`app.js` 在 `?mode=live` 时改拉这个接口（需要动 `adapter.js` 映射）。
**要你确认**：是否愿意动大屏 JS 接入接口（改 `screen/js/`），还是保持 mock + 单独开 `/hadoop` 页？见文末「找你确认」。

### 目标 B：机器学习真跑一个，且能被大屏消费（中优先，出彩加分）
`machine_learning/` 有 C++ 的负荷预测、故障预测等引擎（见 spec-机器学习.md）。两条落地路线任选其一，**选 Python 重实现最省事**：

1. **Python 版预测接口**（推荐）：在 `app.py` 加 `POST /api/forecast`，输入站点+时间，Python 用简单模型（移动平均/线性外推 + 早晚双峰正弦基线，完全照 spec 的"规则+仿真"思路）算未来 1/6/24h 负荷，返回曲线数组。大屏加一个「预测曲线」panel 展示（实线=实际、虚线=预测、阴影置信区间，用 ECharts `areaStyle`）。——这既是"机器学习"又能上大屏，最划算。
2. **复用现有 C++ 引擎**：要在 CentOS7 上编译 `machine_learning/` 的 C++ 并起进程/或包一层 Python 调它。工作量大且 CentOS7 编译 Qt/C++ 环境脆弱，不推荐，除非你想做"真・C++ 算法"。

**验收参照**：做成后，大屏切换站点能看到贴合历史的预测曲线；/hadoop 页或大屏能展示"未来 24h 负荷"。

### 目标 C：老师给大数据后的接入消化（做了前面才轮到，但先想好）
"老师给大数据"通常指：一批 CSV/JSON/数据库导出，几万到几百万行。我们要：
1. **把数据灌进 Hive**（而不是 Excel）
2. **设计一张「大表」结构**，跑几个能体现"大数据处理"的查询（count/group by/join/排序）
3. 相关结果在大屏或 /hadoop 页展示

**具体动作（写进流程，等数据到再做）：**
- 拿到文件 → 丢到 `~/hive_sync/`（可以先造一个解析脚本，按表转 tsv）
- 用 `load_hive.sh` 思路建表+LOAD（注意保留字加反引号、用绝对路径）
- 写几条"大数据感"查询存到 `/hadoop` 页的快捷按钮里：`count(*)`、各分区 topN、join 汇总、`distinct` 用户数等
- 可在 `/hadoop` 页加个小说明文案，演示时点按钮现场跑，最有说服力
- **如果要演示"大数据量量级"**：可以造一张几百万行的 `charge_log` 来展示 Hive 极限（造个脚本 `generate_bigdata.py` 批量生产行 → 灌入 → count 秒回）

## 3. 我们（agent） 怎么帮你们

分工模式（沿用这两天的方式）：
- **你负责**：跑 SecureCRT 命令 / 传文件 / 在 Windows 验证、拍板方向。
- **我们负责**：改代码（`app.py`、大屏 JS、算法 Python、造数据脚本）、告诉你要复制粘哪条命令。

**请 agent 帮忙时的三句话模板：**
1. 「我要把大屏改成查 Hive 的数据，帮我改 `app.py` 加 `/api/snapshot`，并把 `screen/js/` 接上」→ 我们会给出改好的文件 + 传给服务器的 scp 命令 + 验证命令。
2. 「帮我用 Python 写负荷预测接口 }/api/forecast}，并在大屏加预测曲线」→ 照做 + 给验证方法。
3. 「老师给了 [文件名]，帮我把它灌进 Hive 并做几个演示查询」→ 提供解析+灌数+查询脚本。

> 提示：改动集中在**仓库两个地方**即可：`screen/`（网关+前端）和新建的算法目录。尽量避免动 Hive 服务器配置（已调通，别破坏）。
