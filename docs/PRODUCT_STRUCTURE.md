# 00 · 架构总览

面向人的系统全貌。详细的实现规格见各 `spec-*.md`，AI 助手以 `AGENTS.md` 为准。

## 四层架构

| 层级 | 名称 | 回答的问题 | 核心能力 |
| ---- | ---- | ---------- | -------- |
| 第一层 | 用户服务层 | 车主如何最快、最省地充上电 | 智能找站、智能推荐、预约排队、充电服务、结算报告 |
| 第二层 | 设备管理层 | 设备是否健康、故障如何处置 | 设备监控、健康度评估、故障诊断、远程运维、数字孪生 |
| 第三层 | 智能决策层 | 接下来会发生什么、该怎么调度 | 负荷预测、故障预测、需求预测、智能调度、风险识别 |
| 第四层 | 运营分析层 | 经营状况如何、该做什么决策 | 运营驾驶舱、营收分析、碳排分析、what-if 决策仿真 |

四层之间是一条数据闭环：用户行为产生订单与设备数据 → 数据进入智能决策层产出预测 → 预测反过来改变用户侧推荐与运营侧动作 → 动作落地产生新数据。这条闭环是项目核心价值，也是答辩演示主线。

## 子系统划分

| 子系统 | 运行形态 | 面向对象 | 实现规格 |
| ------ | -------- | -------- | -------- |
| 充电用户端 | Linux + Qt 桌面程序（QML，模拟手机交互） | 电动汽车车主 | `spec-用户端.md` |
| 服务器管理端 | Linux + Qt 桌面程序（Widgets，宽屏后台） | 运营管理员 | `spec-管理端.md` |
| 数据库端 | QSQLite，全业务数据存储核心 | 各端共享 | `spec-数据库.md` |
| 大数据可视化大屏 | Web 页面，ECharts 图表 | 运营决策者 | `spec-大屏.md` |
| 机器学习智能分析 | 贯穿各端的算法能力层 | 各端共享 | `spec-机器学习.md` |

## 角色

| 角色 | 使用频率 | 核心诉求 |
| ---- | -------- | -------- |
| 车主（个体用户） | 高频 | 快速找到可用桩、少排队、少花钱、充完自动结算 |
| 运营管理员 | 中频 | 监控设备健康、处置故障、管理用户、看营收 |
| 运营决策者 | 低频 | 从大屏看全局态势，借助 AI 助手与仿真做经营决策 |

三个角色共享同一套底层数据，同一台设备、同一笔订单在不同端以不同视角出现。这一"同数据、多视角"特性是跨端联动的技术基础。

## 通信与数据流

全端通过一个无界面 C++ 服务进程通信：

```
用户端 ─┐
管理端 ─┼─ WebSocket/JSON ─ 服务端进程（QWebSocketServer）
大屏   ─┘        │           ├─ SQLite 读写
                 └───────────┴─ 设备模拟/采集线程（QTimer 定时写库）
```

- 用户端、管理端用 `QWebSocket` 连入，大屏用浏览器原生 `WebSocket` 连入，共用同一套 JSON 消息协议（见 `spec-协议.md`）。
- 各端不直连数据库文件，一律经服务端读写。

## 关键术语

| 术语 | 含义 |
| ---- | ---- |
| SOC | 车辆电池荷电状态（%），当前剩余电量 |
| 快充 / 慢充 | 按功率划分的充电桩类型，快充功率高、耗时短 |
| 负荷预测 | 预测站点未来 1 / 6 / 24 小时的用电负荷与空闲桩数量 |
| 设备健康度 | 综合通信、温度、功率波动、异常次数计算的设备评分（0–100） |
| 削峰填谷 | 用分时电价、积分激励把高峰需求引导到低谷时段 |
| 数字孪生 | 管理端用图形化平面图模拟充电站布局与桩位状态 |
| 运营驾驶舱 | 营收、订单、负荷、告警、用户增长等指标集中的实时看板 |
| what-if 仿真 | 输入假设条件（加桩、降电价、故障）后推演对等待/利用率/营收的影响 |
| 绿色充电指数 | 综合谷时充电比例、绿电比例、负荷降低、碳排减少的绿色度评分 |
| 智能风控 | 基于异常行为（高频预约又取消）计算风险评分并给出处置建议 |

## 功能分级

功能分两级：`【基础】`为老师项目要求书明确列出的必做项；`【增强】`为可加分的增值项，可按精力裁剪。分级标记在 `tasks.md` 与各分端规格中保留，实现顺序先保基础闭环。
